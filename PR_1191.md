## Summary

Added a complete Soroban SDK test suite for the `matching_pool` contract, which previously had only empty placeholder tests and was excluded from the Cargo workspace.

**Test infrastructure**

- Added `contracts/soroban/contracts/matching_pool/Cargo.toml` (keeps `lib.rs` at the crate root via `[lib] path`) and registered the crate in the workspace manifest/lockfile, so `cargo test -p matching_pool` now works.
- Unit tests in `matching_pool/test.rs` (7 cases) exercise the extracted pure `calculate_match_amount` helper: 1:1 and 2:1 ratios, round-down, cap by remaining pool, empty pool, zero contribution and exact boundary.
- Integration tests in `matching_pool/tests/matching_pool_test.rs` (15 cases) register the contract with `Env::default()` and drive it through the generated client.

**Coverage of the requested scenarios**

- Initialization: sponsor, campaign id, ratio, zero balances and `active` status; sponsor auth required.
- Match ratio: 1:1 (`100`) and 2:1 (`200`) payouts with state assertions.
- Pool exhaustion: cap at `remaining_pool`, `exhausted` status, repeated releases returning `0`, empty pool returning `0`.
- Unauthorized callers: missing signature rejected for `initialize`/`fund`/`reclaim`; a different address is rejected by `fund` and `reclaim` even when all auths are mocked.
- Sponsor reclaim: partial match then reclaim returns the unmatched amount and marks the pool `completed`; zero reclaim on an exhausted pool.

**Minimal supporting contract changes**

The original contract had no way to fill the pool (`total_pool`/`remaining_pool` were always `0`) and did not verify that `reclaim`'s argument was the stored sponsor, so the requested scenarios could not be tested through the public API. Added:

- `fund(sponsor, amount)` — sponsor-authenticated pledge that increases `total_pool`/`remaining_pool` and rejects non-sponsors and non-positive amounts.
- Sponsor identity checks in `fund` and `reclaim` (previously a caller signing for itself could reclaim another sponsor's funds).

Documented the new entry point in `contracts/soroban/README.md`. No token transfers were added — the contract's existing accounting-only model is unchanged.
